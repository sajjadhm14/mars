# Mars — بک‌اند یادآوری

تودولیست فارسی با React، Node.js، PostgreSQL و Docker Compose. ثبت‌نام با نام کاربری، ایمیل و رمز عبور است و ورود با نام کاربری و رمز عبور انجام می‌شود. هر حساب فقط تسک‌های خودش را می‌بیند. برای هر تسک عنوان، توضیحات و زمان وارد کنید؛ اگر انجام نشده باشد، یادآوری به ایمیل انتخاب‌شده در پروفایل می‌رود. بسته‌شدن مرورگر اثری روی زمان‌بندی ندارد.

## اجرا

این پروژه در `~/projects/mars` قرار دارد و فرانت‌اند در `~/projects/jupiter` است. هرکدام نصب وابستگی‌ها، lockfile و Dockerfile مستقل دارند؛ npm workspace مشترک وجود ندارد.

دستورهای Docker زیر را داخل `~/projects/mars` اجرا کنید. Compose هر دو پروژه را از مسیرهای مستقل خودشان build می‌کند. نام پروژهٔ Compose و volume دیتابیس حفظ شده‌اند.

نیازمندی: Docker و Docker Compose.

```bash
cp .env.example .env
docker compose up -d --build
```

- برنامه: <http://localhost:3000>
- صندوق آزمایشی Mailpit: <http://localhost:8025>
- بررسی وضعیت: `docker compose ps`
- گزارش ارسال: `docker compose logs -f worker`
- توقف بدون حذف داده‌ها: `docker compose down`

پورت برنامه با `APP_PORT` تنظیم می‌شود. PostgreSQL داده‌ها را در volume پایدار نگه می‌دارد. **دستور `docker compose down -v` داده‌های دیتابیس را حذف می‌کند.**

اگر دانلود npm داخل Docker با مشکل شبکه روبه‌رو شد، فرانت‌اند را روی میزبان build کنید و همان خروجی را در کانتینر Nginx اجرا کنید:

```bash
npm --prefix ../jupiter ci
npm --prefix ../jupiter run build
docker compose -f compose.yaml -f compose.prebuilt.yaml up -d --build
```

هر دو روش React و API یکسانی را اجرا می‌کنند. فایل‌های پیش‌ساخته در `../jupiter/dist` تولید می‌شوند و داخل Git نیستند. پس از ساخته‌شدن ایمیج‌ها، `docker compose up -d --no-build` برای اجرای دوباره کافی است.

## ارسال ایمیل واقعی

تنظیم پیش‌فرض ایمیل را فقط به صندوق محلی Mailpit می‌فرستد و به اینترنت تحویل نمی‌دهد. برای ارسال واقعی، تنظیمات ارائه‌دهندهٔ SMTP خود را در `.env` قرار دهید:

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_REQUIRE_TLS=true
SMTP_USER=your-smtp-username
SMTP_PASS=your-smtp-password
SMTP_FROM=Yadavari <your-verified-address@example.com>
```

برای پورت ۴۶۵ معمولاً `SMTP_SECURE=true` لازم است؛ مشخصات سرویس SMTP ملاک است. فرستنده باید نزد سرویس شما مجاز باشد. سپس:

```bash
docker compose up -d --force-recreate mars worker
```

اطلاعات SMTP فقط سمت سرور می‌ماند. فایل `.env` در Git و build context قرار نمی‌گیرد. آدرس گیرنده از پروفایل صاحب تسک خوانده می‌شود و به localStorage وابسته نیست.

## حساب کاربری و پروفایل

- ثبت‌نام: نام کاربری ۳ تا ۳۲ کاراکتر (حروف انگلیسی، عدد و زیرخط)، ایمیل معتبر و رمز ۸ تا ۱۲۸ کاراکتر. نام کاربری و ایمیل یکتا هستند؛ بزرگی و کوچکی حروف برای ورود و یکتایی تفاوتی ندارد.
- ورود: **نام کاربری + رمز عبور**. ثبت‌نام موفق به‌صورت خودکار وارد حساب می‌شود.
- پروفایل از بالای صفحه یا پایین نوار کناری باز می‌شود. فیلد «می‌خواهید ایمیل یادآوری به کدام حساب برود؟» در ابتدا با ایمیل ثبت‌نام پر است.
- تغییر ایمیل یادآوری، ایمیل ثبت‌نام یا نام کاربری را عوض نمی‌کند. دکمهٔ «استفاده از ایمیل ثبت‌نام» آدرس پیش‌فرض را برمی‌گرداند؛ سپس تغییرات را ذخیره کنید.
- یادآوری‌های ارسال‌نشده، از جمله تسک‌های قبلی، به آدرس جدید می‌روند. موارد قبلاً ارسال‌شده دوباره ارسال نمی‌شوند. ارسال شروع‌شده ممکن است به آدرس قبلی برسد.
- نشست ورود ۷ روز اعتبار دارد، با خروج باطل می‌شود و در PostgreSQL نگهداری می‌شود. رمز با scrypt و salt تصادفی هش می‌شود؛ دیتابیس فقط هش توکن نشست را ذخیره می‌کند.
- کوکی نشست `HttpOnly` و `SameSite=Strict` است. برای استقرار HTTPS مقدار `SESSION_COOKIE_SECURE=true` را تنظیم کنید. بررسی Origin و محدودیت تلاش ورود هم فعال است.
- migration داده‌های قبلی را حذف نمی‌کند. تسک‌های نسخهٔ تک‌کاربره به اولین حساب ثبت‌شده منتقل می‌شوند و پیش از آن ارسال نمی‌شوند.
- تأیید ایمیل و بازیابی رمز عبور در این نسخه پیاده‌سازی نشده‌اند.

## رفتار یادآوری‌ها

- هر تسک یک زمان یادآوری دارد و گیرنده از پروفایل صاحب آن خوانده می‌شود؛ یادآوری تکرارشوندهٔ روزانه در این نسخه وجود ندارد.
- زمان ورودی مطابق منطقهٔ زمانی دستگاه و با تاریخ میلادی است. نمایش تاریخ‌ها فارسی است؛ دیتابیس زمان را با `TIMESTAMPTZ` ذخیره می‌کند.
- بررسی پیش‌فرض هر ۱۵ ثانیه است؛ زمان دریافت دقیق به صف و سرویس ایمیل بستگی دارد.
- یادآوری عقب‌افتاده پس از بالا آمدن مجدد سرویس بررسی می‌شود؛ سرویس و میزبان باید روشن باشند.
- تسکی که تکمیل آن پیش از شروع ارسال ثبت شده باشد ایمیل نمی‌گیرد. ارسال شروع‌شده یا ایمیل تحویل‌شده قابل لغو نیست.
- بعد از پذیرش ایمیل توسط SMTP، یادآوری دوباره ارسال نمی‌شود. پذیرش SMTP لزوماً به معنای رسیدن به Inbox نیست.
- خطای ارسال با تأخیر افزایشی از ۳۰ ثانیه تا سقف یک ساعت، حداکثر ۱۰ بار تلاش می‌شود. سپس وضعیت «ارسال ناموفق» و دکمهٔ تلاش دوباره نمایش داده می‌شود.
- تغییر زمان چرخهٔ ارسال تازه‌ای ایجاد می‌کند. تغییر عنوان، ایمیل پروفایل یا برداشتن تیکِ تسکِ قبلاً ارسال‌شده باعث ارسال دوباره نمی‌شود. تغییر ایمیل پروفایل، تلاش‌های ناموفقِ تسک‌های در انتظار را از نو فعال می‌کند.
- قفل سطری PostgreSQL جلوی پردازش هم‌زمان یک یادآوری را می‌گیرد. اگر فرایند دقیقاً بعد از پذیرش SMTP و قبل از ثبت موفقیت در دیتابیس متوقف شود، امکان ارسال تکراری وجود دارد؛ تضمین exactly-once در SMTP وجود ندارد. Message-ID ثابت برای retry استفاده می‌شود، اما تضمین حذف تکرار نیست.

## ساختار

```text
~/projects/jupiter/     فرانت‌اند React + Vite؛ package.json، lockfile و Dockerfile مستقل
~/projects/mars/src/    API، حساب کاربری، دیتابیس و worker
~/projects/mars/test/   تست‌های یکپارچه
~/projects/mars/compose.yaml    اجرای کل برنامه از دو مسیر مستقل
```

ارتباط فرانت‌اند با بک‌اند از طریق HTTP و مسیر `/api` است.

Nginx فرانت‌اند را سرو می‌کند و `/api` را به Node.js می‌فرستد. API و دیتابیس پورت عمومی ندارند و پورت‌های وب فقط به `127.0.0.1` متصل‌اند. همهٔ مسیرهای تسک و پروفایل نشست معتبر می‌خواهند. برای دسترسی عمومی HTTPS و کوکی Secure را فعال کنید؛ صندوق آزمایشی Mailpit را عمومی نکنید.

## تست

پس از بالا آمدن سرویس‌ها:

```bash
docker compose exec -T mars npm test
```

تست‌ها schema مجزا می‌سازند و به داده‌های اصلی دست نمی‌زنند. برای تست تحویل واقعی SMTP به Mailpit، فقط با تنظیمات ایمیل محلی:

```bash
docker compose exec -T -e TEST_MAILPIT=true mars npm test
```

پوشش ۲۲ تست: CRUD، زمان‌بندی، رقابت workerها، retry، SMTP واقعی محلی، ثبت‌نام و ورود، هش رمز، نشست و خروج، نشست منقضی، جداسازی کاربران، محدودیت تلاش ورود، محافظت Origin، ماندگاری پروفایل، تغییر گیرندهٔ یادآوری و migration داده‌های قبلی. همهٔ تست‌ها در schema مجزا اجرا می‌شوند.

## توسعه بدون Docker برای Node.js

Node.js ۲۰٫۱۹ یا بالاتر و PostgreSQL در حال اجرا لازم است:

```bash
npm ci
export DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/todo
npm run dev
# در ترمینال دوم با همان متغیر دیتابیس:
npm run worker
# در ترمینال سوم، فرانت‌اند:
cd ~/projects/jupiter
npm ci
npm run dev
```

در توسعه، Vite درخواست‌های API را به پورت ۳۰۰۰ پروکسی می‌کند. برای build فرانت‌اند، داخل `~/projects/jupiter` دستور `npm run build` را اجرا کنید.
